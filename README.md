# پنل خرید مکمل — راهنمای راه‌اندازی

یک وب‌اپلیکیشن خصوصی برای دو نفر (کارفرما و مسئول خرید) با دیتابیس مشترک.
فناوری: Next.js + TypeScript + Tailwind (RTL فارسی) + Supabase (Postgres, Auth, RLS) + Vercel.

> **وضعیت صادقانه:** این پروژه هنوز **منتشر نشده** و لینک اینترنتی ندارد. ساخت حساب Supabase/Vercel/GitHub باید با حساب خودتان انجام شود. مراحل زیر همه‌چیز را قدم‌به‌قدم توضیح می‌دهد (حدود ۳۰ تا ۴۰ دقیقه).

---

## انتشار رایگان روی GitHub Pages (توصیه‌شده برای ایران)

این پروژه به‌صورت **سایت ایستا** ساخته می‌شود (`output: "export"`): همه‌چیز در مرورگر اجرا و مستقیم با Supabase صحبت می‌کند و امنیت دسترسی‌ها با RLS در دیتابیس تأمین می‌شود. برای انتشار روی Vercel هم همان مقادیر محیطی کافی است.

1. مخزن را **Public** کنید (Settings → General → Danger Zone → Change visibility). GitHub Pages در پلن رایگان برای مخزن خصوصی کار نمی‌کند. در کد هیچ رازی نیست.
2. Settings → **Pages** → بخش Source را روی **GitHub Actions** بگذارید.
3. Settings → **Secrets and variables → Actions → Variables** → دو متغیر بسازید:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` (مقدارش کلید `publishable` یا `anon` است، نه `secret`/`service_role`)
4. فایل `.github/workflows/deploy.yml` را در مخزن بسازید. با هر تغییر در شاخهٔ `main` سایت خودکار ساخته و منتشر می‌شود (تب Actions).
5. آدرس سایت: `https://<نام‌کاربری>.github.io/<نام‌مخزن>/`

> صفحهٔ جزئیات محصول با آدرس `/product/?id=...` باز می‌شود (نه `/products/<id>`).

## مرحله ۱ — ساخت دیتابیس در Supabase

1. در <https://supabase.com> ثبت‌نام کنید و **New project** بزنید (نام دلخواه، رمز دیتابیس را جایی ذخیره کنید، Region نزدیک به شما).
2. وقتی پروژه آماده شد، از منوی چپ **SQL Editor** را باز کنید.
3. محتوای فایل `supabase/migrations/0001_schema.sql` را کپی و **Run** بزنید.
4. محتوای فایل `supabase/migrations/0002_rls.sql` را کپی و **Run** بزنید.
   (ترتیب مهم است. هر دو باید «Success» بدهند.)

## مرحله ۲ — بستن ثبت‌نام عمومی

در Supabase: **Authentication → Sign In / Providers** (یا Settings):

- گزینه **Allow new users to sign up** را **خاموش** کنید.
- **Email → Confirm email** می‌تواند روشن بماند (اسکریپت ساخت کاربر ایمیل را تأییدشده ثبت می‌کند).

حتی اگر کسی حسابی بسازد، چون نقش ندارد، به هیچ داده‌ای دسترسی نخواهد داشت.

## مرحله ۳ — گرفتن کلیدها

در Supabase: **Project Settings → API**

- `Project URL` ← برای `NEXT_PUBLIC_SUPABASE_URL`
- `anon public key` ← برای `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `service_role key` ← برای `SUPABASE_SERVICE_ROLE_KEY` (**محرمانه؛ فقط روی کامپیوتر خودتان**)

## مرحله ۴ — اجرای پروژه روی کامپیوتر و ساخت دو کاربر

نیازمند نصب [Node.js 20 یا بالاتر](https://nodejs.org).

```bash
npm install
cp .env.example .env.local
```

فایل `.env.local` را باز کنید و مقادیر را پر کنید: سه کلید مرحله ۳، و ایمیل/رمز (حداقل ۱۰ کاراکتر) برای دو کاربر.
سپس:

```bash
npm run create-users
```

این دستور دو حساب (کارفرما و مسئول خرید) را می‌سازد و نقش آن‌ها را ثبت می‌کند.
بعد از آن می‌توانید رمزها را از `.env.local` پاک کنید.

برای امتحان محلی:

```bash
npm run dev
```

و <http://localhost:3000> را باز کنید.

## مرحله ۵ — ذخیره در GitHub

1. در GitHub یک مخزن **Private** بسازید.
2. پروژه را در آن آپلود کنید (`.env.local` به‌صورت خودکار نادیده گرفته می‌شود و آپلود نمی‌شود).

## مرحله ۶ — انتشار روی Vercel

1. در <https://vercel.com> با GitHub وارد شوید → **Add New → Project** → مخزن را انتخاب کنید.
2. در بخش **Environment Variables** فقط این دو مقدار را اضافه کنید:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`

   **کلید `service_role` را در Vercel وارد نکنید.**
3. **Deploy** بزنید. اگر بیلد خطا داد، متن خطا را برای من بفرستید تا رفع کنم.
4. آدرس `https://….vercel.app` همان لینک برنامه است. آن را برای کارفرما بفرستید.

## مرحله ۷ — تنظیم نهایی Supabase

در Supabase: **Authentication → URL Configuration** → مقدار **Site URL** را آدرس Vercel بگذارید.

## کنترل دسترسی‌ها (در سطح دیتابیس)

| کار | کارفرما | مسئول خرید |
|---|---|---|
| ساخت/ویرایش/بایگانی محصول | ✅ | ❌ |
| تأیید یا رد خرید | ✅ | ❌ |
| ثبت و ویرایش استعلام | ❌ | ✅ |
| تغییر وضعیت به «خریداری‌شده» (فقط پس از تأیید) | ❌ | ✅ |
| مدیریت همکاران | ✅ | ✅ |
| دیدن تاریخچه تغییرات | ✅ | ❌ |
| حذف داده | ❌ | ❌ (بایگانی/غیرفعال‌سازی) |

## قوانین مقایسه قیمت

- ارزان‌ترین قیمت فقط میان استعلام‌های «موجود» حساب می‌شود.
- از هر فروشنده فقط **آخرین** استعلام در مقایسه شرکت می‌کند؛ قبلی‌ها تاریخچه‌اند.
- قیمت ≤ هدف: نشانگر سبز. بالاتر از هدف: هشدار زرد.
- استعلام قدیمی‌تر از **۴۸ ساعت** گزینه قطعی نیست و «نیازمند استعلام مجدد» نمایش داده می‌شود (مقدار در `src/lib/compare.ts`).

## تست‌ها

```bash
npm test                      # منطق مقایسه قیمت و اعتبارسنجی ورودی
psql "$DATABASE_URL" -f tests/rls_test.sql   # فقط روی یک دیتابیس خالی و آزمایشی!
```

> اسکریپت `tests/rls_test.sql` نقش‌ها و جدول `auth` را شبیه‌سازی می‌کند؛ **هرگز روی دیتابیس واقعی Supabase اجرا نکنید.**

## ساختار پروژه

```
supabase/migrations/   جدول‌ها، تریگرها، سیاست‌های RLS
scripts/create-users.mjs   ساخت امن دو حساب
src/app/               صفحات (ورود، داشبورد، محصولات، لیست خرید، همکاران، اعلان‌ها)
src/components/        فرم‌ها و اجزای رابط
src/lib/               منطق مقایسه، اعتبارسنجی، قالب‌بندی، اتصال Supabase
tests/                 تست‌ها
```
